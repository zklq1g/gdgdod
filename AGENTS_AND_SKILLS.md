# Agents and Skills Breakdown

This document details the configuration, constraints, and roles of the active agents and skills in the RCA ecosystem.

## 1. RCA Agent (`rca_agent.py`)

The **RCA Agent** acts as the core reasoning engine. It operates in a two-stage pipeline: Narrative Generation and Structured Extraction.

### Core Configuration
- **Model**: Gemini (Flash)
- **Temperature**: `0.2` (Narrative) / `0.1` (Structured Extraction) - Kept deliberately low to minimize creative deviations and enforce strict adherence to log data.
- **Constraints**: Enforces a "Zero Hallucination" rule. The agent is explicitly prompted: *"every claim MUST cite the exact log line... If no log evidence exists, write [Evidence Not Found]."*

### Agent Tooling & Resilience
- **Leaky Bucket Limiter**: Prevents HTTP 429 Rate Limit errors by throttling requests to 10 RPM.
- **Deterministic Cache**: Generates SHA-256 hashes of the combined logs and feedback. Cache hits instantly return previous results, saving API quotas and reducing latency to zero.
- **Exponential Backoff**: Uses the `tenacity` library to automatically retry failed requests with a jittered backoff.
- **Streaming Output**: The narrative report is streamed token-by-token to the frontend via a Python generator, providing real-time feedback during long analyses.
- **Revision Loop**: Accepts optional human feedback and re-generates the report in a loop until the engineer approves.

## 2. Jira Skill (`jira_skill.py`)

The **Jira Skill** is a deterministic, non-LLM function that acts as a downstream processor for the RCA Agent's output.

### Core Configuration
- **Role**: Data formatting and schema validation.
- **Trigger**: Activated automatically upon the Human-in-the-Loop (HITL) approval step in the Streamlit UI. No manual "generate" step is required.

### Skill Execution Flow
1. **Extraction**: Uses Regex to isolate the minified JSON array generated by the RCA Agent's secondary prompt.
2. **Schema Validation**: Ensures keys like `Title`, `Description`, `Priority`, and `Assignee` exist and conform to expectations.
3. **Data Transformation**: Converts the JSON array into a Pandas DataFrame.
4. **Export (Adapter Pattern)**: Exposes two export paths via the UI:
   - **Direct Push Simulation**: Simulates an Atlassian API call, generates realistic `ENG-XXXX` ticket IDs, and displays clickable hyperlinks — demonstrating the integration pattern without ADF format complexity.
   - **CSV Bulk Import**: Formats the DataFrame into a CSV file optimized for Jira's Bulk Issue Import functionality.

## 3. Streamlit Frontend (`ui.py`)

The **Frontend** is not a passive view layer — it manages workflow state and enforces the human-in-the-loop contract.

### State Machine
The UI transitions through the following states in order:
`idle` -> `uploaded` -> `generated` -> `revision` (optional loop) -> `approved`

### Key UI Behaviors
- **Instant Ticket Parsing**: The Jira DataFrame is generated silently at the moment of approval, eliminating a redundant intermediate step.
- **Split Export Panel**: Upon approval, engineers are presented with two side-by-side options — Direct Push or CSV Download — with no additional clicks required.
- **Light Theme Enforcement**: A `.streamlit/config.toml` forces the light theme globally, preventing the user from switching to dark mode.
- **Fallback Recovery**: If the LLM fails to produce structured JSON action items, a "Regenerate Action Items Only" recovery button appears without requiring a full re-analysis.
